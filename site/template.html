Toolkit research · 100 apps · 10 categories · researched November 2026

Can we build the toolkit today? For 41 of 100 apps, yes. For 49 the API exists but something stands in the way. 10 are blocked.

A multi-agent pipeline researched auth, access gating, API surface and MCP for each app and cited the vendor's own docs for every answer. Four verification loops took field accuracy from 74% (model memory) to 92.5% on a 30-app sample checked against vendor docs by independent verifier agents, and to 90% on a holdout the loops never saw. No human verified the labels; every sampled answer carries a URL and quote so anyone can audit it.

The agent

What I built, and where the agents needed a judgment call

An orchestrator fans the 100 apps out to parallel research workers that share one prompt, one JSON schema and one labelling rubric. Every later stage is a verification loop that either recomputes a label from evidence or proposes a patch with a vendor URL and quote. No record changes silently: all field changes are logged with the loop that made them.

Judgment calls (made by the orchestrator agent, no human)

  • Defining the labels. Pass 2 workers disagreed on what "official MCP" and "gated" mean. The orchestrator agent wrote rubric.md: an announced or docs-search-only MCP is not official; the gate is the most restrictive one a toolkit serving other people's accounts would hit.
  • Policy calls the evidence can't settle. The orchestrator decided these, and a human owner should review them: An app with no REST API but an official remote MCP (Otter) counts as buildable with friction, not blocked. An API key and a pasted bearer token count as the same auth for scoring. Local CLIs (Mermaid, Sherlock) are not SaaS APIs; they become sandboxed tools with no auth.
  • Adjudicating disagreements. When the blind ground-truth agent and the research agent disagreed, the orchestrator agent re-read both cited vendor pages and decided. The verifier itself was wrong twice (Podio and WhatsApp MCPs exist).
  • Pages agents can't read. JS-rendered pricing tables (Devin) and checkmark icons came through WebFetch blank and needed a real browser.
  • Still needs a human: nobody has hand-checked the labels yet. human_review.csv lists all 120 sampled answers with proof links for that audit.
  • Long-tail apps. Paygent Connect, iPayX and fanbasis have no findable developer docs. One vendor page also carried hidden text addressed to LLM summarisers; the worker ignored it and flagged it.

Verification

How I know the table is right: measured, not asserted

I drew a stratified random sample of 30 apps (3 per category, seed 2026) and split it in two. Sample A (20 apps) was used to find error patterns and tune the loops. Sample B (10 apps) was held out: no loop was designed using it, so its score is the honest estimate for the 70 apps outside the sample. Ground truth came from blind verifier agents reading only vendor pages, then the orchestrator agent adjudicated every disagreement by re-reading both cited pages. No human was involved, so this measures agreement with carefully sourced agent labels, not with a human expert. Scored fields: toolkit auth, access gate, official MCP, verdict (4 × 30 = 120 checks).

Proof

Run it yourself

Source repo: github.com/PiyushJadhav11/Product-Ops-Research-Project-

The repo holds the prompts, schema, rubric, every intermediate pass, the ground-truth files and the scripts that produced each number on this page. The deterministic loops run offline in seconds. The research stage needs an Anthropic key, and a Composio key if you want Composio's Firecrawl toolkit to do the page fetching.

git clone https://github.com/PiyushJadhav11/Product-Ops-Research-Project-.git && cd Product-Ops-Research-Project-

# reproduce every number on this page from the committed data (no keys needed)
python agent/lint.py      data/pass2/pass2.json
python agent/normalize.py data/pass3/patched.json data/pass3/patched_norm.json
python agent/score.py     data/pass1/pass1.json all      # 74.2%
python agent/score.py     data/pass2/pass2.json all      # 86.7%
python agent/score.py     data/pass3/patched_norm.json B # 90.0% holdout

# re-run the research agent on any app(s)
export ANTHROPIC_API_KEY=...   COMPOSIO_API_KEY=...   # Composio optional
python agent/run.py research --ids 41-50 --out data/run/ecom.json
python agent/run.py fix --in data/run/ecom.json --out data/run/ecom.patches.json

The submitted dataset came from Claude agents running these exact prompts with web search and fetch tools (10 research workers, 3 blind verifiers, 5 fix-loop workers, plus browser checks). agent/run.py is the same loop as a standalone script against the Anthropic API. It is syntax-checked but had not been run end to end at submission time.

Research run 23 Nov 2026. Vendor pricing and gating change often, so every claim links to the page it came from. Labels follow agent/prompts/rubric.md.
